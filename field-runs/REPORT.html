F-ENV-1: documented sudo apt install libvips is insufficient on Ubuntu 22.04

CONTRIBUTING.md says to install libvips via apt. Ubuntu 22.04 ships libvips 8.12.1; Rails 8.1 then refuses to boot: “libvips’s unfuzzed operations are not safe to use with untrusted content… requires libvips 8.13 or later and ruby-vips 2.2.1 or later.” Verified twice in logs/bin-setup.log (RETRY2). Worked around for this run with prebuilt libvips 8.18.7 (see ENV.md); the documented instruction alone does not produce a bootable app on this common LTS. Environment/docs finding, not necessarily an app bug.

F-BASE-1: spec/extras/github_spec.rb:14 observed failing repeatedly on the pinned tree + required Ruby (3 runs; non-flakiness not proven)

  • Command: bundle exec rspec spec/extras/github_spec.rb (also in full-suite baseline, logs/baseline-rspec.json)
  • Error: NoMethodError: undefined method ‘parse’ for class CGI
  • Cause verified: Ruby 4.0.9 (the version .ruby-version REQUIRES at this pin) ships cgi 0.5.1, where CGI.parse no longer exists (ruby -e ‘require “cgi”; p CGI.respond_to?(:parse)’ => false).
  • Real code path affected: extras/github.rb:21 ps = CGI.parse(res) inside Github.token_and_user_from_code (GitHub account linking). The spec comment says it exists to prove CGI.parse is loaded. On the required Ruby this feature would raise at runtime.
  • Observed failing in the original full-suite baseline plus 2 subsequent isolated reruns (3 observed runs total; logs/baseline-failures-recheck.log). Repeated failures observed; 3 runs do not prove non-flakiness.

F-BASE-2: spec/features/user_administration_spec.rb:39 “banning” observed failing repeatedly (3 runs; non-flakiness not proven)

  • Command: bundle exec rspec spec/features/user_administration_spec.rb (also in full-suite baseline)
  • Error: RSpec::Expectations::ExpectationNotMetError: Expected 0 to eq 1. Failing expectation: line 50 expect(sent_emails.size).to eq(1) - banning a user sends no notification email on the pinned tree.
  • Context: pinned history includes 2026-10-21 commit e646f63a “restore transactional + notifications email; not yet mailing list mode”; the pinned tree appears mid-repair of the email subsystem. Not investigated further - root-cause triage is reserved for the independent fresh-context triager per protocol.
