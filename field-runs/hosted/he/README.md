# Human Essentials hosted recipe (preparation draft)

Status: NOT run-proven. Nothing here has been executed. Doctor has no verdict. No map or replay exists.

Modes (workflow_dispatch, one per run, frozen recipe constants required):
- doctor: one `bundle exec saboteur doctor --suite` at the PR 5723 head ace6151d2296a3b252d5ccdbcc4a838caf2d388c. At the pin this runs the unchanged suite twice internally, so one invocation is the gate. Red or incomplete is preserved raw and is a block, not an exclusion.
- map: whole-suite map at one era snapshot (S1 ace6151d, S2 6453a3de, S3 1085e87e, S4 2857b48f), `saboteur run --all --baseline-passes 1 --max-duration 35m --jobs 1 --verbose`, stopped at a validated boundary. The triple (coverage-K.json, inputs-K.json, whole-suite-map-v2) is uploaded unchanged with a sealed manifest. Exit 130 is a deliberate stop, not a pass and not row admission.
- replay (outer bound 2700s, the recorded historical value; the native pr preset also applies its own 10m max-duration): at the PR ledger head H (HEAD == H checked, B = H^1), the triple of that PR's era is restored byte for byte from a completed map run, then `saboteur pr --since B --jobs 1 --verbose --json --html`.

Fixed canonical root: every job uses /opt/he-app. Coverage keys are canonical absolute paths and are never rewritten, so the producer and consumer must share it. The replay checks that inputs.root equals sha256 of that root and that runtime and settings digests equal values computed in the same job from the pinned tool's own constants.

Environment (upstream: Rails importmap/Sprockets, no JS package manager, so no yarn/npm step exists; a tree with one blocks): ubuntu-latest, Ruby 3.4.3, postgres:14.24 digest-pinned service (PG_HOST/PG_USERNAME/PG_PASSWORD), headless Chrome from the runner image, assets precompiled as an environment step (not an exclusion), one install/mutation worker, baseline_timeout 3600 (provisional, a new environment, not comparable with earlier sandbox timings). The gem is built in the job from the pin and compared with the pin's lib/exe (the handoff gem is not reused).

Evidence limits carried into any row: confirmation is bounded (initial executed IDs plus at most 8 pointer-covering IDs per survivor, default 300s budget, not an exhaustive suite union); Stryker `executed` is merged across phases, so phase-specific IDs may be unavailable and are never reconstructed by subtraction; the inputs JSON is diagnostic; an exact cache-key miss at replay is expected; snapshot-to-head drift (including routes.rb for S4 members and the 5656 Gemfile comment typo) is disclosed, not a zero-drift claim; controls and map evidence are not study admission; every survivor needs fresh independent triage.

partial_coverage stays at the pin's default (off): at this pin scoped runs (--since, pr) confirm survivors against the restored whole-suite pointer with no partial_coverage opt-in (lib/saboteur/engine.rb:296-299, confirm_survivors; survivor_confirmation.rb header describes the unscoped partial case). The effective value is asserted as off and recorded.

Admission: map and replay require a green doctor run (same workflow commit, same frozen recipe, same Ruby and identity digests) and replay requires a map run verified through the GitHub API (workflow path, head_sha equal to this run's, event, conclusion, artifact name for that run). Replay also gates on identical original lock, installed lock, config, custom-map and ignore presence+hash, with Gemfile differences limited to comments. A snapshot triple that changed during replay is quarantined (exit 1). The lock gate allows only the approved saboteur addition (exact GEM and DEPENDENCIES lines, prism already locked).

Not yet specified or proven: job-time feasibility (the 6h job limit may not fit a map with two baseline-scale passes on this suite; the doctor evidence must inform a reviewed budget before any map); and whether Bundler 4.0.19 adds a CHECKSUMS section or otherwise rewrites the lock during the local install (the lock gate fails closed until that output is reviewed). The map command (`run --all --baseline-passes 1 --max-duration 35m`) and the replay outer bound (2700s) are the recorded historical values, not new choices; the doctor cap 9600s is the only new outer allowance.

## Budgets and evidence gaps (provisional, new environment)
- baseline_timeout 3600 is a provisional value from an unfinished local validation, not calibrated hosted evidence. The doctor cap of 9600s (two 3600s pass budgets plus 2400s margin) is a new allowance, not a measurement and not the earlier 7800s outer bound; the phase cap is unchanged.
- Map: one unchanged baseline plus one coverage pass under a single 35m whole-run cap (historical command). The doctor, not the map, supplies the two-pass stability gate. The pinned run budget may refuse a cold map that cannot fit; if so, a budget change must be proposed and reviewed before any further map is dispatched.
- Source for the two passes: doctor_command.rb:14 and baseline_health.rb:43-45 (check_run(1) then check_run(2)). Seed: the recipe sets none for HE; the native default applies and is recorded (inputs JSON seed); it is not the Lobsters seed-3 flow. Bundler: the exact version in the lock's BUNDLED WITH is installed and used (BUNDLER_VERSION); how that Bundler writes CHECKSUMS into the lock on install is ungrounded here, and a new CHECKSUMS section currently fails the lock gate closed. Doctor success proves both passes ran and matched through the tool's own checks; per-pass executed-ID lists are NOT retained as artifacts and are not claimed. Stryker `executed` is merged across phases, so phase-specific confirmation IDs are unavailable and not reconstructed. The doctor result on S1 does not speak for the other eras, whose own baselines can still fail.
- No registry saboteur: ordinary locked gems are fetched by exact lock string into vendor/cache, then `bundle install --local`; the built gem is the only saboteur in the cache.
- Recorded identity: Postgres server version and diaper_test collation, service image id, browser path/version, CI/RAILS_ENV/PG variables (no password), locale. The app sets its own time zone; it is not replaced.
- Drift is reported as H to S commit count and ancestry, per member.

## Environment decisions (labelled, not parity claims)
- Postgres: the study used 14 locally; upstream CI uses 12.3; this recipe uses the postgres:14.24 image with initdb -E UTF8 --locale=C (matching the recorded study server 14.24, UTF8, C); the tag digest is recorded at run time, not pinned here, and the hosted environment is new, and the run records `select version()`, collation and the service image id. It claims neither upstream parity nor era parity.
- CI=true (set by Actions) changes the app's test eager-load behavior; it is recorded in env-identity.txt, not overridden. The app's own America/Los_Angeles time zone is kept.
- Pointer confirmation: at the pin, scoped runs (--since, pr) read the whole-suite pointer when `cache` is true (CoverageStore#whole_suite_map) and confirm survivors with no partial_coverage dependency (engine.rb:296-305 at the pin). partial_coverage therefore stays at the default off, and the gate asserts effective cache=true and partial_coverage=off.
- Instrumentation additions to the lock: exactly the saboteur spec with the built gem's runtime dependencies (read from the built gem) plus its DEPENDENCIES line; each dependency must already be locked.

- Seed: historical HE runs never overrode the seed; the pin default 1 applies. The gate asserts effective seed == 1 and the snapshot seed is compared to 1. Seed is not part of the cache key; this is metadata compatibility, not a determinism claim.
- Prior interrupted CSV-order failures are not attributed to locale.
