# method_swap

Swaps a method with its counterpart: `min` with `max` and `any?` with `all?` are boolean or ordering opposites, while `map` with `each` is a swap of the same iteration with a different result (`map` returns the mapped array, `each` returns the receiver). Only the message bytes change; receiver, arguments and block stay intact. A receiver is required, so a bare `max(a, b)` Kernel call is left alone. The `each`/`map` pair is also left alone where the call's return value is syntactically discarded: a non-last statement, and - recursing from a discarded statement - the tail expression of an if/elsif/else/unless/case/when branch, a begin/rescue body, or a while/until body, whose value the loop never observes. Both names run the same block, so the swap is treated as equivalent there (#399, #440). The one exception is detected syntactically: a `.lazy` call in the receiver chain keeps the swap, because `lazy.map` defers its block. A lazy enumerator reached through a variable, parameter or instance variable is not detected, so its `each`/`map` swaps in a discarded position are suppressed even though `map` would not run the block (#431). A call whose value flows into a predicate, receiver, block result, or control-flow argument stays swappable. Arid expressions and nested definitions are skipped; the normal parser, dedupe and cap checks apply.

Runs by default. Use `--operators method_swap` to select it alone, or `--exclude-operators method_swap` to leave it out. A swap can be equivalent when the test's inputs make both names return the same value and the test depends only on that value: a one-element collection for `min`/`max`, or a nonempty collection on which a pure predicate is uniformly false (or uniformly true) for `any?`/`all?`. Matching return values alone do not prove equivalent effects: `all?` short-circuits at the first false where `any?` keeps scanning, so a block with side effects is called a different number of times. An empty collection is not a case either (`any?` returns false, `all?` true). Review the result and effects rather than assuming a survivor is a bug.

Closes the operator gap reported in #237: `[[x, lo].max, hi].min` previously got only whole-body mutants.
