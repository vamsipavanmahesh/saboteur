Your tests pass.
Do they test anything?

saboteur changes your Ruby code in small ways, one change at a time. If your tests still pass, saboteur shows you the exact change they missed. It runs only the tests that touch each change, so it is fast, and it never counts a broken test as a catch.

How it works

Line coverage tells you which code ran. It does not tell you if a test would notice when that code breaks. Mutation testing does.

Change

saboteur finds your methods and makes one small change per mutant: flip a <, swap && for ||, delete a line, empty the whole method.

Run only the tests that matter

A per-test coverage map tells saboteur which tests ran the changed line. Only those run, likeliest killers first. The first failure stops the run.

Check the kill

Every kill is run again on the unchanged code. If that test fails there too, it is not a kill. This removes fake kills.

Read the survivors

You get a score and a diff for each survivor. A survivor means a missing test, or code that does not matter.

# Billing::Invoice#total  - survived
-   return 0 if quantity >= 10
+   return 0 if quantity > 10
# No test uses quantity = 10. Add one.

Why saboteur

Built for real Rails suites, not only small gems.

Picks tests per mutant

Only the tests that executed the changed statement run. A change no test reaches is reported as "no coverage", not as a survivor.

No fake kills

A kill must fail on the mutant and pass on the original. In the benchmark, 0 of 20 checked kills on lobsters were fake.

Coarse first

Each method body is replaced with nil and with raise first. If your tests miss that, saboteur says so and skips the small changes for that method. Less noise.

Diff mode

--since origin/main changes only the methods you edited on this branch. Quick enough for a pull request.

Rails and parallel

Run with --jobs N workers. Each worker gets its own database copy. Tested on a Rails 8.1 app on Postgres with 6 workers, with the same verdicts as 1 worker.

Safe to run

Each mutant runs in a watched child process. Everything it starts is tracked and killed. There are limits on time, memory and process count.

Open report

JSON in the Stryker mutation-testing-report format, so existing viewers can open it.

Repeatable

Every test run starts from the same random seed. Pass --seed to repeat a run.

Extendable

Add your own mutations by file and byte range, add hooks around each mutant, or write an adapter for another test framework.

Quickstart

Needs Ruby 3.3 or newer on Linux or macOS. RSpec only, by design.

1. Install

gem install saboteur
# or in your Gemfile
gem "saboteur", group: :test

2. Turn off SimpleCov for the run

saboteur needs Ruby's Coverage for itself. Most projects already guard SimpleCov with an environment variable.

3. Run it

bundle exec saboteur run                          # whole project
bundle exec saboteur run --since origin/main      # methods changed on this branch
bundle exec saboteur run --subject 'Billing::Invoice#total'
bundle exec saboteur run --subject Billing        # a namespace
bundle exec saboteur run --incremental            # reuse verdicts that did not change
bundle exec saboteur run --jobs 6                 # parallel workers

4. Configure (optional)

# .saboteur.yml
include: [lib/**/*.rb]
exclude: [lib/my_gem/version.rb]
timeout_factor: 3        # deadline = 3 x the tests' recorded time
max_memory_mb: 2048      # memory growth cap per mutant
max_processes: 64
seed: 1

5. Accept a survivor with a reason

# .saboteur-ignore.yml
- subject: "Billing::Invoice#total"
  mutation: "1a2b3c4d5e6f7a8b"
  reason: "equivalent: amounts are always whole cents"

An entry without a reason is rejected. Exit codes: 0 no survivors, 1 survivors, 2 bad configuration, 3 the tool failed. The JSON report goes to .saboteur/report.json.

Memory after the fork-sharing change (hashie)

Paired A/B runs against the pre-PR commit (32c0f21), 5 pairs per job level with AB/BA alternation and cold caches, on a 2 vCPU / 2 GB shared sandbox. Peak memory is per-process-tree PSS from /proc/smaps_rollup sampled at 0.3s. Verdict parity: 0 verdict differences in 23,700 mutant outcomes (1,580 mutants x 15 pairs); kill reasons (assertion vs crash class) vary run to run on both variants, as before.

jobspeak PSS baseline (median, range)peak PSS PR (median, range)shared-memory delta

Peak RSS is unchanged (median ~660 MB at jobs=6 both variants): the PR does not touch less memory, it keeps more of it shared between workers after fork, which is what PSS measures. On machines running many parallel workers this is the difference that keeps the box out of swap.

Wall time on uncontended runs: 30-36s for both variants at every job level (no regression; per-cell minimums 48s vs 49s at jobs=1, 32s vs 31s at jobs=2, 30s vs 32s at jobs=6, PR first). The shared sandbox had multi-minute CPU-starvation windows during this session (walls up to 594s); affected runs are flagged via sampler cadence and excluded from wall analysis. Absolute times are specific to this 2-core sandbox.
