## Findings

### 1. Block header and hint describe a different mutant than the one shown (medium)

Claim: docs/guides/reading-survivors.md, "`assertion_gap` - the mutated
expression produced a different value while the covering tests ran". The
block hint reads "a test ran this mutant, the value changed, and no assertion
noticed".

Repro: fixture with `def self.total(qty) = 12 * qty + 0 * qty` (main has
`12 * qty`), specs `spec/shop/pricing_spec.rb` (`total(0) == 0`) and
`spec/flows/checkout_flow_spec.rb` (`total(10) > 0`). On main run
`saboteur run --all`; on a branch with the edit run `saboteur pr`.

Actual: block 1 header is `[result unchecked · assertion gap · #1 of 2
blocks]` with the text "a test ran this mutant, the value changed", and the
diff shown is `+` to `-` (id 0e3d9355c46f7d0d). That mutant cannot change the
value (`x + 0*qty` and `x - 0*qty` are equal). report.json, `saboteur
survivors` and the agent JSON all list 0e3d9355c46f7d0d as input_gap, and
report.json has valueDiffered false. `--quiet` prints
`[assertion_gap] - 0e3d9355c46f7d0d`. The header comes from another mutant in
the same statement group.

Expected: the sentence about the value changing should not be attached to a
mutant whose own value never changed; or the block should say the label is
the statement's strongest signal.

Suggested acceptance scenario: statement with one equivalent mutant and one
mutant killed-by-nothing with a changed value; assert the block does not say
"the value changed" next to the equivalent mutant's diff.

### 2. README contradicts itself on whether `pr` confirms survivors (low)

Claim (README, "Flakiness contained"): "Default inferred-spec runs, `pr`
included, skip it." Claim (README, "Know the limits"): "PR and `--since` runs
then confirm survivors against specs they did not load."

Actual: `pr` with a whole-suite map from main ran confirmation
("confirmation: 8 survivors killed by specs this run didn't load, 11
confirmed"). Without the map it skipped it.

Expected: the first sentence says "without a whole-suite map".

Suggested acceptance scenario: README claim check that `pr` with a map
prints a confirmation line.

### 3. Agent JSON has no `kind` or `gapKind` (low)

Claim: docs/guides/reading-survivors.md, "Both JSON reports add the additive
`kind` field next to `classification` and `gapKind`".

Actual: `saboteur pr --agent` findings have `classification` only; `kind` and
`gapKind` are absent on every shown finding (checked with and without a map).
report.json has both. The doc does not say which two reports it means.

Expected: name the two reports, or add the fields to the agent JSON.

Suggested acceptance scenario: `pr --agent` on the money fixture; assert
line 52 carries a kind.
