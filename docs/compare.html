Two open-source tools for Ruby

saboteur and mutineer are both MIT-licensed Ruby mutation testers that mutate one change at a time, run the covering tests and report what survived. The facts below come from each project's README, gemspec and RubyGems page.

Details worth knowing, all from the projects' own pages:

  • Stryker is one design across three languages with more than 30 mutators and a shared report schema, mutation-testing-elements. saboteur's JSON report conforms to that schema, so Stryker dashboards and report viewers can read it.
  • PIT made mutation testing practical on the JVM by being fast and integrating with existing build tooling, and its docs recommend the same workflow saboteur's pr preset targets: run frequently against only the changed code.
  • Infection reports more than 33 million installs, enforces a Mutation Score Indicator in CI with --min-msi, and its --git-diff-lines mutates only the lines a pull request touched.
  • mutmut remembers completed work so runs resume incrementally, and ships an interactive terminal browser for inspecting and re-testing mutants.
  • cargo-mutants is a cargo subcommand; it builds each mutant and runs the crate's tests to find code that tests reach but do not check.

Shared lineage

saboteur's design notes record the public work it builds on in docs/prior-art.md:

  • Mutation testing itself: DeMillo, Lipton and Sayward (1978), surveyed by Jia and Harman (2011).
  • Diff-based mutation, arid-node suppression and surfacing survivors in review: Google's mutation testing papers (Petrović et al., 2018 and 2021).
  • Coarse method-body mutations: Pitest's descartes research, concept only.
  • The JSON report format: Stryker's mutation-testing-elements schema (Apache-2.0), output format only.

No source code, specs or fixtures from other mutation testing tools are used.

Where saboteur puts its effort

  • RSpec-only, done properly. One framework lets the coverage map tie each method to the exact examples that cover it, so each mutant reruns only those. Why no Minitest.
  • Verified kills. Every fresh kill is re-checked against the unchanged code; a kill the suite cannot confirm is rejected and stays out of the score. Timeout checks, other errors and cached kills reused by --incremental are not re-checked. See rejected kills.
  • Built for pull requests. The pr preset scopes the run to changed methods with a 10-minute budget, and the GitHub Action runs advisory by default on every pull request.
  • Safety controls. A hazard guard, canary values, and time, memory and process-count limits on every mutant; a Landlock sandbox on Linux 6.2 and newer.
  • Made for agents. A stable agent JSON output with a documented deprecation policy.
